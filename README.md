# FH6 涂装查看器 (FH6 Livery Viewer)

**[English](README_en.md) | 中文**

在游戏外浏览《极限竞速：地平线 6》本地存档中的涂装：缩略图平铺、显示**具体车型**与**作者**、可缩放的大图预览。解决游戏内涂装管理界面看不到车型、无法预览纹饰的问题。

**只读工具 —— 不会修改任何存档文件。**

## 功能特性

- 🖼️ **缩略图平铺**：直接读取存档自带的 `bigThumb` 预览图，卡片墙展示全部涂装
- 🏎️ **显示具体车型**：内置 671 辆车的 ID 对照表（与游戏数据逐条对齐；v1.3.0 已按游戏 6.420.696.0 复核——无新车，按游戏 ModelShort 年份后缀修正 9 处年份；v1.3.1+ 又按游戏运行时内存的「完整车名文案」（`gamemem.read_car_years()`）补全 52 处年份，今游戏内显示一致；v1.7.2 又经 2026-09 人工逐条校对——新增 11 辆、修正 48 条既有条目），不再对着一串数字猜车
- ⬇️ **车型名表在线更新**（v1.8.0）：车型名对照表支持在线更新，**程序更新与数据更新解耦**——官方加入新车后无需等待发布新版，维护者更新数据后用户端下次启动即自动检查拿到新表（默认开启，可在「设置」中关闭）；按界面语言自动优选 Gitee / GitHub 数据源（另有 CDN 镜像兜底），下载内容经严格校验（大小/结构/条目数），全部失败时静默继续使用本地数据，内置表永远兜底，无任何遥测
- 📍 **游戏内位置**：每个涂装标注它在游戏「我的涂装」里的行列位置（缩略图角标 + 详情），可按游戏内顺序排列，照着就能在游戏里翻到
- 🎯 **自动定位**：详情面板直接给出从 1行1列 出发的最短方向键路径（利用首尾环绕），「自动定位到游戏」按钮一键切到游戏并发送方向键，精准跳到目标涂装
- 📌 **窗口置顶**：一键把窗口浮在游戏上方，玩着游戏随时查涂装、按定位
- 🔃 **自动检测存档更新**：「设置」里的开关（默认开，本地持久化），轮询当前存档目录（3s 轮询 + 2s 防抖）；游戏里新下载/删除涂装后无需手动点「刷新」——新涂装以插入方式进入卡片墙，选中项与滚动位置保持不变，状态栏提示「检测到存档更新: +N 新增 / -M 删除, 已刷新」；可随时在设置里关闭，手动「刷新」按钮保留原语义（可靠性加固：目录暂不可访问时自动暂停并提示一次、恢复后自动恢复检测；刷新失败自动回滚待重试；header 解析未完成的条目后台退避重试、写完自愈）
- 🔄 **重复涂装检测**：感知哈希两两配对推断重复涂装，无预制模式——判定条件由用户在筛选栏右侧「重复检测参数」按钮弹出的对话框里自由组合：车型相同/不同、作者相同/不同、图片感知哈希距离阈值（或任一方无预览图文件）、名称相似度阈值、创建时间/下载时间相同/不同、图层数相同/不同（v1.8.0 新增：同层数是重复的强信号，但跨设计撞层数也常见，宜与同车/同作者联用），七个维度任意叠加，同时满足所选条件的两条涂装判为重复并按传递关系合并成组；对话框内置 4 个常用「模板」一键填表（同车微调、跨车型移植、同名异版、多次下载），再次打开自动回填上次应用的值，与某模板完全一致时自动选中该模板名。出厂默认 = 同车型且图片距离 ≤6；确定后即用已缓存特征毫秒级重算（改动仅本次运行有效，不落盘）；分析按需触发，不筛选则零开销。v1.8.0 修正「创建时间」语义：改用涂装文件内嵌的作者创作时间（此前误用下载时间），「同名异版」「多次下载」两模板判定更准
- 🗂️ **重复涂装分组展示**：打开「仅显示重复涂装」后，卡片墙按重复组聚拢并在每组前显示通栏组标题行（第 N 组 · 成员数）；排序方式同时作用于组间和组内
- 🟢 **已喷涂检测**（v1.8.0 重做）：读游戏缩略图缓存里的「在册名单」清单（`CacheThumbnails/.manifest`）判定哪些涂装正喷在车上——**不开游戏、不扫内存、零风险**。启动/切换存档即自动标记（零点击零确认零弹窗）：已上车涂装贴琥珀橙 `#E69F00` 喷漆罐角标（卡片左上角，色盲友好；当次会话内常显，无需任何开关，切换存档后自然消失），游戏中喷涂/卸下涂装约 3 秒内自动跟随。清单不可用（缓存缺失/损坏）且清单中途出现时由轮询自动补检；仅在开启喷涂筛选且清单不可用时才可能走内存扫描兜底（原理与风险确认框，确认后只读扫描游戏进程内存，不写、不 hook、不附加调试器，需游戏运行中）——顶栏按钮已随 v1.8.0 移除，检测全自动。另有「仅显示已喷涂」「仅显示未喷涂」两个筛选开关（互斥），加详情面板喷涂状态与状态栏计数；清单不可用时显示「待检测」，绝不会把「读不到」误判成「未喷涂」
- 🏷️ **拍卖涂装（SoulBoundLivery）**：显示从拍卖行买来的涂装——它们以 `SoulBoundLivery` 容器存在、容器内没有缩略图，工具自动从游戏 `CacheThumbnails` 缓存定位对应 `GUID.webp` 预览图（缓存缺失时显示「(无预览图)」；v1.8.0 修复：同一涂装在缓存里有多个候选图时不再留空，自动择优——优先取正喷在车上的那张，否则取最新写入的一张）。拍卖卡左上角带拍卖锤角标（默认灰=未应用/未检测，确认喷在车上时变琥珀橙 `#E69F00`）；「涂装筛选」新增「仅显示拍卖涂装」与「只显示非拍卖涂装」两个互斥来源开关、「显示无预览图的拍卖涂装」开关（默认关——无预览图的拍卖涂装默认不显示，打开后才显示），以及「仅显示已应用拍卖涂装(在车上)」「仅显示未应用拍卖涂装(不在车上)」两个互斥开关（与「已喷涂/未喷涂」互斥，未检测时优先读缓存清单自动判定，不可用才走同款确认门）；右键新增来源快筛「只显示拍卖涂装 / 只显示我的设计」。拍卖条目的标题/作者在数据里本就是哨兵/空，故显示「拍卖涂装」+ 车型、作者为 "?"，且没有游戏内位置（不能自动定位）
- ⚡ **性能优化**：卡片墙单 Canvas 虚拟绘制（v1.4.0 重构），滚动流畅不闪屏；缩略图线程池后台解码（180 张约 0.36s，不卡 UI）、重复检测并行化（实测 3.74x）、内存全量扫描并行提速（稳定约 3.9s）
- 🔍 **车型表内存校对**（v1.3.1）：新增 `gamemem.read_car_strings()`，运行时从游戏内存读取 `Data_Car` 的 DisplayName / ModelShort 串表，重新生成并校对 `cars.json`，修正多处车型名；同时优化缩略图解码失败时的保留旧图与退避重试
- 🌐 **多语言界面**（v1.6.0）：简体中文（默认）、English、日本語、한국어、繁體中文 五种语言，按下载包内 exe 文件名自动选择（如 `FH6LiveryViewer_en.exe` 即英文界面），无需任何设置
- 🔤 **数据字体 Consolas**（v1.6.0）：卡片与详情里的用户数据文本（涂装名/车型/作者等）用 Consolas 显示，`I` 与 `l` 一眼可辨（微软雅黑里两者都是光杆竖线）；中文/日文/韩文字符经 Windows 字体链接自动回退，无缺字；卡片三行字号整体 +1（名称 10 号加粗、车型/作者 9 号）且卡片整体放大，更易读

- 🏭 **车厂筛选**：按车厂快速过滤（保时捷、法拉利……）
- 🔍 **可缩放预览**：卡片右键菜单「查看缩略图」（或详情面板「查看大图」/ 双击右侧预览图）打开大图，滚轮缩放（5%–1200%）、拖动平移、原始尺寸/适应窗口
- 📅 **下载日期排序**：按涂装写入存档的时刻排序（新→旧/旧→新），也可按名称/车型/作者/车厂/游戏内顺序排序；可另选「次选」条件作为第二关键字（默认「无」=不启用），分组展示下同时作用于组间与组内
- 🗂️ **分组显示**：可按车厂、作者或车型为卡片墙分组（通栏标题行标明组名与数量，组间顺序跟随当前排序，取不到值的归入『其他』并置底；按车型分组时组名为车型显示名，未识别车型的自成一组）；选中任一维度时会自动把主选排序切换为对应模式，组间按该维度顺序排列
- 🔎 **搜索**：按涂装名/作者/车型过滤；双搜索框可同时输入两个关键字做与组合（两框中间的「+」即此意），只填第一个框时等同单关键字搜索
- ⚡ **右键快筛**：卡片右键菜单「只显示该车型」「只显示该作者」快速聚焦；激活时筛选按钮文案出现「快筛」段，同一菜单顶部「清除快筛」即可复原（切存档自动清空）
- 📋 **原生复制**：详情文本可选中复制（Ctrl+C / 右键菜单），卡片右键菜单复制位置/名称/车型/作者
- 💾 **一键备份**：把整个存档目录打成 zip（只读操作）
- 🖥️ **双版本存档支持**：Steam 版（userdata）与商店/Xbox 版（`XboxGames\GameSave\pgs`）自动识别

## 环境要求

- Windows 10/11
- Python 3.10+
- [Pillow](https://pypi.org/project/Pillow/)（`pip install pillow`）——用于解码 FH6 存档的 WebP 预览图；不装也能运行，但涂装缩略图无法显示

## 下载

[Releases](https://github.com/Hx-zh/fh6-livery-viewer/releases) 提供五个 zip，区别只在界面语言（程序按包内 exe 文件名自动选择语言）：

| zip（`vX.Y.Z` 为版本号；语言标签为 BCP 47） | 界面语言 |
|---|---|
| `FH6LiveryViewer_vX.Y.Z_win64_zh-CN.zip` | 简体中文 |
| `FH6LiveryViewer_vX.Y.Z_win64_zh-TW.zip` | 繁體中文 |
| `FH6LiveryViewer_vX.Y.Z_win64_en.zip` | English |
| `FH6LiveryViewer_vX.Y.Z_win64_ja.zip` | 日本語 |
| `FH6LiveryViewer_vX.Y.Z_win64_ko.zip` | 한국어 |

## 快速开始

```bash
pip install pillow
python app.py
```

启动后自动定位本机 FH6 存档（Steam 读注册表，商店版扫描 `XboxGames\GameSave\pgs`），也可以用「手动选择目录…」指定 `remote` 或 `ContainersRoot` 目录。

## 打包发布

```bash
python -m PyInstaller FH6LiveryViewer.spec
```

产出为单文件 `dist\FH6LiveryViewer.exe`，`cars.json` 已内嵌（运行时只读，不释放到 exe 旁；v1.8.0 起在线更新的车型表缓存写入 `%LOCALAPPDATA%\FH6LiveryViewer\`）。构建一次后，把 exe 复制改名为 `FH6LiveryViewer_zh-CN.exe` / `_zh-TW.exe` / `_en.exe` / `_ja.exe` / `_ko.exe`（BCP 47 语言标签）即得到对应语言的界面（程序按自身文件名选语言；开发时可用环境变量 `FH6_LANG=en` 等覆盖）。


## 使用说明

| 操作 | 说明 |
|---|---|
| 单击卡片 | 选中，右侧显示大图与元数据（名称/车型/作者/游戏内位置/按键路径/创建时间/下载时间/层数/大小/重复组）——v1.8.0 起原「日期」拆为两行：创建时间（文件内嵌的作者创作时间）与下载时间（玩家下载/保存时刻），均显示为 `YYYY-MM-DD HH:MM:SS (UTC±hh:mm)` 带时区后缀 |
| 双击卡片 | 自动定位到游戏内该涂装（等同详情面板「自动定位到游戏」按钮） |
| 右键卡片 | 弹出菜单：查看缩略图 / 定位到涂装位置 / 只显示该车型、只显示该作者（右键快筛，激活时菜单顶部「清除快筛」复原）/ 复制游戏内位置、名称、车型、作者 |
| Ctrl+C | 焦点在详情框时复制选中文本；否则复制选中涂装的游戏内位置 |
| 「涂装筛选」 | 全部为独立开关，可叠加组合；首次打开任一依赖重复分析的开关时才后台分析重复涂装，不筛选零开销。含拍卖涂装专用开关——「仅显示拍卖涂装」（来源过滤，打开后只显示拍卖涂装、隐藏「我的设计」）与「只显示非拍卖涂装」（与其互斥，隐藏全部拍卖涂装）、「显示无预览图的拍卖涂装」（默认关；无预览图的拍卖涂装默认不显示，打开后才显示），以及拍卖涂装应用状态开关——「仅显示已应用拍卖涂装(在车上)」「仅显示未应用拍卖涂装(不在车上)」（两者互斥，也与「已喷涂/未喷涂」互斥；未检测时优先读缓存清单自动判定，清单不可用才走确认门回退内存扫描，取消则开关回退无效） |
| 「重复检测参数」 | 筛选栏右侧的独立按钮：4 个常用模板一键填表 + 七个维度自由组合判定条件（车型/作者/图片/名称/创建时间/下载时间/层数，见功能列表），再次打开自动回填上次设置，「恢复默认」回到出厂条件（同车型 + 图片距离 ≤6）；确定即用缓存特征重算并自动勾选「仅显示重复涂装」直接查看结果（条件本身仅本次运行有效） |
| 「置顶」 | 窗口浮在游戏上方，随时调用 |
| 「自动检测存档更新」 | 「设置」内开关（默认开，本地持久化）：检测到存档目录变化（新下载/删除涂装）后自动增量刷新——新卡插入式进入卡片墙，选中项与滚动位置保持不变；关闭后回到纯手动，「刷新」按钮语义不变 |
| 「自动定位到游戏」 | 立即把游戏窗口切到前台并发送方向键，跳到选中涂装（游戏未运行则提示）；发送中再点按钮或按 Esc 取消。前提：「我的设计」刚打开（焦点在 1行1列）且未开游戏内筛选 |
| 「设置」 | 调整自动定位的按键节奏（按下保持 + 键间间隔，毫秒，确定后保存到 `%LOCALAPPDATA%\FH6LiveryViewer\config.json`，重启仍生效，不写注册表）；「自动检测存档更新」开关（默认开，即时生效并本地持久化）。实测周期阈值约 30ms，低于它会吞键；默认 15+50=65ms（因低帧率卡顿吞键反馈从 40ms 放宽），仍有需要可再加大。另有「车型名表(在线更新)」区块：显示内置/在线两份车型表的信息（条数、更新时间与来源，谁在生效标注「（当前生效）」）；复选「自动检查车型表更新(联网 Gitee/GitHub)」（每次启动自动检查一次；与按键节奏、存档更新开关同存于 config.json）；「恢复内置数据」按钮（重读内嵌表并清除在线缓存）；车型表当前状态与「检查车型表更新」按钮在主界面右下角页脚（「更新链接」行尾另有「检查软件更新」——查询双端 release 最新版本，有新版时提示打开下载页）；底部另有「打开配置目录」（资源管理器打开 `%LOCALAPPDATA%\FH6LiveryViewer\`，可查看/备份数据文件） |
| 「车厂」 | 按车厂过滤 |
| 「备份整个存档」 | 存档目录打包 zip 到 `backups\` |
| 「所在文件夹」 | 在资源管理器中定位该涂装 |

卡片三行信息：涂装名 / 车型名（可换行完整显示）/ 作者。车型未识别时第三行显示 `ID xxxx + 日期`。卡片缩略图区右上角角标为游戏内位置（`N行M列`，「我的涂装」按车型分组、每列 2 个）；已上车涂装卡片左上角另贴喷漆罐角标（v1.8.0 起启动/切换存档后按缓存清单自动标记，当次会话内常显，无需开关，切换存档后消失），两者一左一右共存。**拍卖涂装卡片**无游戏内位置角标（不在「我的涂装」网格），左上角贴的是拍卖锤角标（默认灰=未应用/未检测，确认喷在车上时变琥珀橙，取代喷漆罐角标）；其名称行显示「拍卖涂装」、作者为 "?"（FH6 未存原作标题/作者信息）。

## 存档格式说明

工具对存档**只读**。以下格式结论来自本机真实存档验证与社区逆向：

- **Steam 版**：`<Steam>\userdata\<用户ID>\<appid>\remote\`（FH6 appid `2483190`），每个涂装是一组同名分片文件：`Livery_<车型ID>_<- 时间戳>.header / .C_livery / .bigThumb.png …`
- **商店/Xbox 版（pgs）**：`<盘符>:\XboxGames\GameSave\pgs\u_<ID>\<快照号>\ContainersRoot\`，每个涂装是一个同名文件夹（`header` / `C_livery` / `bigThumb.webp`）。`current` junction 指向活跃快照，快照号会滚动（100→101…），工具已自动跟随
- **拍卖涂装（SoulBoundLivery）**：拍卖行买到的涂装以 `SoulBoundLivery_<车型ID>_<14位时间戳>` 容器落在 `ContainersRoot` 下，容器内**没有**缩略图文件；预览图来自游戏 `CacheThumbnails` 缓存（`CacheThumbnails/.manifest` 含两张表——第一表=GUID/物化表、第二表=逻辑名注册表；逻辑名格式 `<车型ID>_<16hex instanceKey>(bm<N>|u<26位 token>)_bigThumb.webp`）。工具由 SoulBoundLivery header 末 16 字节经 Crockford Base32 编码出 26 位 token，查第一表得到 `CacheThumbnails/<GUID>.webp` 作为预览图（缓存位于 `%LOCALAPPDATA%\ForzaHorizon6\LocalStorage_Cache\CacheThumbnails`，商店版机器亦落在该路径）。缓存缺失/损坏时拍卖条目降级为「无缩略图」，不影响其它功能
- `header` 为二进制元数据（版本/名称/作者/创建时间/图层数/车型 ID），布局见 `fh6save.py` 注释
- 文件名时间戳（UTC，界面已转本地时区）= 玩家下载/保存该涂装的时间；作者创作时间内嵌于 header（UTC，已转本地），两者独立（v1.8.0 起界面分别显示为「下载时间」「创建时间」）

## 上游项目

本项目的存档 header 解析逻辑基于上游项目 **[Arstz/FH6_livery_unlocker](https://github.com/Arstz/FH6_livery_unlocker)**
的逆向成果，并用本机 FH4/FH5/FH6 真实存档做了校正（FH6 header v7 的图层数/车型 ID 偏移为本项目补充）。
遵照上游，本项目同样以 **AGPL-3.0** 开源。

车型 ID 对照表最初来自 [HDR 的 FH6 Car Ordinals](https://gist.github.com/HDR/0659d1717bc61504bf83750628963f4f)，现已与游戏内 `Data_Car.str` 字符串表逐条对齐（671 辆）；2026-09 由 McEvofusion 人工逐条校对（新增 11 辆、修正 48 条既有条目）。年份以游戏运行时内存的完整车名文案（`gamemem.read_car_years()`，来自解密后的游戏数据）为权威来源（2026-08-31 校正 52 处）。
